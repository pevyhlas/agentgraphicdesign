Native libraries in the SkiaSharp and HarfBuzzSharp native-assets packages
--------------------------------------------------------------------------------
The CLI and MCP tool packages redistribute libSkiaSharp from
SkiaSharp.NativeAssets.Linux.NoDependencies, SkiaSharp.NativeAssets.macOS and
SkiaSharp.NativeAssets.Win32 4.148.0, and libHarfBuzzSharp from
HarfBuzzSharp.NativeAssets.Linux, HarfBuzzSharp.NativeAssets.macOS and
HarfBuzzSharp.NativeAssets.Win32 14.2.0, for every runtime identifier those
packages carry.

Upstream notice, redistributed verbatim
---------------------------------------
All six packages ship the same THIRD-PARTY-NOTICES.txt (SHA-256
21504c46c4c58aa64c1055bd2dcbc5f9a136b4b8c412ed3cc6740e22c5b127f5). It is
redistributed unmodified, byte for byte, as THIRD-PARTY-NOTICES-SKIASHARP.txt,
next to this file in the repository and at the root of both tool packages. It
reproduces the upstream notices for Skia, HarfBuzz, FreeType, libpng, zlib,
libjpeg-turbo, libwebp, Expat, piex, the Adobe DNG SDK and the SPIR-V Headers,
which are compiled into these binaries, and applies to them as written.

That file covers every Skia and HarfBuzz build configuration, so it also lists
ANGLE, etc1, a GIF decoder, ICU, imgui, jsoncpp, libmicrohttpd, SDL, sfntly and
SPIR-V Tools, and its zlib section mentions a mozzconf.h header. None of them is
compiled into these binaries: they belong to Skia's tools, viewers and other
build configurations, and the zlib copy Skia milestone 148 pins has no
mozzconf.h. The binaries mention ANGLE only in OpenGL extension names and
renderer-string checks, their ETC1 code is Skia's own texture code rather than
the etc1 library, Skia decodes GIF with Wuffs, and no ICU library code is
compiled into either binary.

Supplementary notices
---------------------
The sections from Wuffs through the Unicode Character Database below cover the
components compiled into at least one of these binaries that the upstream
notice does not list, identified from the source paths in the Windows debug
symbols the Win32 packages ship and from the symbol and message strings in the
Linux and macOS libraries. Which of them a given runtime identifier contains
depends on its platform (for example the Chromium zlib optimizations on Linux
and Windows, D3D12 Memory Allocator on Windows). Each section reproduces the
upstream license and copyright lines at the revisions Skia milestone 148 and
HarfBuzz 14.2.0 pin, except that, to keep this file plain ASCII, the copyright
sign is written as (c).
