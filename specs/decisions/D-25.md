# D-25 Versioned, immutable, producer-stamped asset kits

**Decided by**: architecture review (capability design closure, all four lenses, change 007); the
owner allowed kits from source builds when their build stamp truthfully says so (R-13); pipeline
and release-contract review when built · **Date**: capability design, pre-public history ·
**Cited by**: R-13, C-06, D-08, D-24, D-29, change 013 slice S09

Status: accepted; built by slice S09 of change 013, not opened yet.

## Decision

### Definition

- A kit is the optional `kit { name, version, root }` block of manifest v2 (D-24): one grammar,
  one parser. Outputs are relative to `<root>/<version>/`; `outputRoots` is forbidden with it.
- `name` matches `[a-z0-9][a-z0-9-]{0,63}`; `version` is SemVer 2.0 over `[0-9A-Za-z.-]` (no
  `+`), at most 64 characters; `root` is confined, link-free and overlaps no input.

### Publication

- Kits use a generic Core `GenerationPublisher`: a write-once generation directory, a descriptor,
  and publication by a **no-replace** rename (`renameat2(RENAME_NOREPLACE)` on Linux;
  `renamex_np(RENAME_EXCL | RENAME_NOFOLLOW_ANY)` through the Darwin backend of change 008). Other
  platforms, Windows included, refuse `kit build` with `ASSET_PLATFORM_UNSUPPORTED`; an unsupported
  filesystem (`EINVAL`, `ENOSYS`, `ENOTSUP`) is `KIT_FILESYSTEM_UNSUPPORTED`.
- An exclusive root lock `<root>/.agd-kit.lock`, inspected and opened without following links,
  waits up to 30 s, then `KIT_LOCKED`.
- The guarantee is namespace-level visibility only, never crash- or power-loss atomicity across
  files. This is the first scoped instance of coherent multi-output publication; crash and
  lost-response outcomes and multi-generation switching stay open (change 014) and would extend
  this publisher rather than add a second one. Atlases will reuse it.

### Descriptor `<root>/<version>/agd-kit.json` (`agd-kit/1`)

- No timestamps; arrays ordinal-sorted; only root-relative POSIX paths in every generated
  artifact.
- Fields: `format`, `name`, `version`, `producer` (the producer v1 record of D-29 verbatim:
  `buildKind: bundle|source`, `sourceDirty`, `label`; no release value; `buildKind` is a claim and
  only a consumer's approved pin proves approval), `runtime {framework, rid}`,
  `algorithms {geometry}`, `inputs {manifestSha256, files[{path, sha256}], bundled[{id, sha256}],
  inputsSha256}` and `files[{path, sha256, bytes, mediaType, target, sizes}]`.
- The input closure is every file the build reads: manifest, family and axes files, members, the
  families, axes files and masters behind every checked placement, and each font file. System fonts
  are refused (`KIT_SYSTEM_FONTS`). `inputsSha256` hashes the sorted input list plus the manifest
  hash and excludes bundled resources and algorithm identities, so an AGD upgrade alone yields
  `exists` with an info notice rather than refusing every existing version.

### Commands

| CLI | MCP | Behaviour |
|-----|-----|-----------|
| `kit build <manifest> [--require-bundle-producer]` | `build_kit` | under the root lock; an existing version renders nothing: render-free integrity check and descriptor name and version check, then an equal stored input hash is `exists` (exit 0, any platform, no byte comparison), otherwise `KIT_VERSION_IMMUTABLE` (exit 7); a new version renders in memory into `.agd-kit-staging-<guid>/` with its `.agd-staging` marker written first, writes and verifies the files, then publishes with a no-replace rename |
| `kit check <manifest>` | `check_kit` | read-only, render-free, platform-independent (for brand-only CI): exact inventory and hashes (`KIT_INTEGRITY`, exit 2), changed inputs `KIT_SOURCES_CHANGED` and a missing version `KIT_VERSION_MISSING` (exit 6); regenerated bytes are not compared |
| `kit verify <version-dir> [--expect-sha256 H] [--require-bundle-producer]` | `verify_kit` | consumer side, no sources: always integrity; reports `pinned` and `consumerApproved` (true only with a matching pin); prints the producer label; without a pin it says "self-consistent, not pinned" |
| `kit pack <version-dir> -o file.zip` | `pack_kit` | `verify` first, then a deterministic stored ZIP |

- Producer policy: `--require-bundle-producer` refuses when the running build is a source build
  and, on the `exists` path, when the stored descriptor says source; on `kit verify` it requires
  `--expect-sha256` (`KIT_PIN_REQUIRED`), so a self-asserted build kind is never accepted unpinned.
- Staging cleanup runs only under the lock, only for marked real (non-link) staging directories
  directly under the inspected root, never following links; unmarked staging is reported, never
  deleted. `--regenerate` is deferred.
- `kit verify` safety (`filesystemTrust = trusted-quiescent-local`: content untrusted, no
  concurrent hostile replacement): descriptor ≤ 4 MiB and depth ≤ 16; paths relative, normalized,
  case-insensitively unique, `[A-Za-z0-9._/-]`, ≤ 4096 files; a bounded walk (≤ 4097 entries,
  depth ≤ 64) never crossing directory links; inspection before opening (links, FIFOs, devices and
  multi-link files refused); reads bounded by the listed size + 1; extra files are
  `KIT_INTEGRITY`.
- `kit pack`: the output must not resolve inside the kit root or version directory; written to a
  temporary sibling opened without following links, then renamed; each entry's SHA-256 and CRC-32
  computed in the read that writes it and compared with the descriptor; sorted portable ASCII
  names, stored method, fixed 1980-01-01 timestamp, mode 0644, no extra fields, no ZIP64
  (asserted); CRC-32 from a shared Core helper.
- MCP confines every path, including the pack output. `KIT_INTEGRITY` is exit 2 in every kit
  command; exit 7 is new (D-27).

### Git-first (D-08)

Kit definitions and version directories are tracked files the user commits; consumers pin
`name@version` plus the descriptor hash, which `docs/kits.md` names as the only trust anchor. No
database or index; AGD never drives Git; the staging directory and the lock file are documented as
ignorable.

### Verification (slice S09)

Depends on D-29's producer record (change 009), S06, S08 and change 008 (macOS inspection and the
Darwin no-replace rename). Increments: the publisher with `kit build` and `kit check`; `kit verify`,
`kit pack` and the MCP tools. Cases: a changed input → exit 7; an upgrade that changes only bundled
resources or the geometry identifier → `exists` plus info; the bundle-producer policy on `exists`
with a stored source descriptor refused; `exists` despite per-platform PNG bytes; `exists` with a
tampered file → `KIT_INTEGRITY`; byte flip, extra, missing, link and FIFO entries → `KIT_INTEGRITY`
without hanging; a re-hashed tampered bundle kit passes unpinned (`pinned: false`) and fails
pinned; `KIT_PIN_REQUIRED`; `KIT_SOURCES_CHANGED` on source and placement-master edits;
`KIT_SYSTEM_FONTS`; version grammar and case aliases; two concurrent builds (one wins, the other
`exists` or `KIT_LOCKED`, its staging untouched); interrupted-build cleanup; unmarked staging kept;
planted links at the lock and pack paths refused; pack inside the root refused; a change between
verify and pack fails; byte-identical packs against hand-built golden bytes and a `ZipArchive`
read-back; no absolute paths.

## Alternatives

- **A committed manifest output root**: not immutable, and consumers would need sources and AGD.
- **A content-addressed store with an index**: a managed store, close to the rejected ledger
  (D-08).
- **A separate `kit.json` grammar**: duplicates manifest v2. **Kit-specific staging and
  rename**: duplicates the coherent-publication work.
- **`ZipArchive` for writing**: platform-dependent header fields and compression variance; stored
  entries lose little because payloads are already compressed.
- **Regeneration comparison**: fails across platforms, and brand CI does not need it.
- **Bundle-only kits** (owner option B): blocks brand changes between releases.

Assumption: kits fit the existing 64 MiB output budget, or the budget is raised through review.

## Revisit when

Consumers need signatures; several kits need a coherent generation switch; cross-platform raster
identity becomes qualified (regeneration comparison could return).
