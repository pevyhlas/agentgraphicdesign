# D-22 Stroke outlines and knockouts as baked derivations in format 1

**Decided by**: architecture review (capability design closure, all four lenses, change 007);
document-format review when built · **Date**: capability design, pre-public history ·
**Cited by**: C-09, D-12, D-21, change 013 slice S07

Status: accepted; built by slice S07 of change 013 after change 011, not opened yet. Additive to
format 1 (C-09).

## Decision

A `path` node may carry an optional `derivation`, a recipe whose baked `d` stays authoritative for
every renderer, exporter, bounds computation, lint, sheet and analysis; none of them change.
Transient documents strip derivations. Older readers keep the field (extension data) and render
`d`; they cannot detect staleness or prevent `d` edits, and newer readers then report `DERIV007`
(declared in `docs/format.md`, schema and changelog).

```json
{ "type": "path", "id": "…", "d": "M12.5,3L…C…Z", "style": { "fill": { "tokenRef": "ink" } },
  "derivation": { "op": "boolean", "algorithm": "agd-geometry/1",
    "params": { "operation": "difference" },
    "operands": [ { "node": "<outline id>", "geometry": "fill" },
                  { "node": "<cutter id>", "geometry": "painted", "offset": 1.2, "join": "round" } ],
    "tolerance": 0.01, "inputsHash": "sha256:…", "outputHash": "sha256:…" } }
```

### Ops and operands

| `op` | Operands | Params | Result |
|------|----------|--------|--------|
| `stroke` | one centerline | optional `width`, `cap`, `join`, `miterLimit` overrides, else the source stroke | the D-21 stroke region |
| `offset` | one | `distance`, `join` (default round), `miterLimit` (default 4, [1, 1000], miter only) | the D-21 offset |
| `boolean` | ≥ 2 | `operation` union, intersect, difference or xor; no fill rule | difference and intersect take the first operand against the union of the rest; xor is parity |

- An operand descriptor is `{node, geometry: fill|stroke|painted, offset?, join?, miterLimit?}`
  naming a node of the same document. `fill` is the shape area under the node's own fill rule,
  whatever its paint; `stroke` the stroke region (empty without a stroke); `painted` the fill area
  when a fill paint exists united with the stroke region.
- `offset` is in [−1e6, 1e6], non-zero when present, and only on boolean operands. `join`
  (`miter|round|bevel`, default round, the constant-distance clearance) and `miterLimit` (default
  4, [1, 1000], only with miter) are allowed only with an offset. The canonical descriptor writes
  the resolved join and limit, so omitted and explicit defaults hash alike.
- Miter or bevel on stroke or painted geometry is unsupported; the supported form is two steps (a
  `stroke` derivation, then its fill), each measured against its own ideal.
- Operands are rectangles, ellipses, lines, polygons and paths. Text, frames, groups, images and
  unknown nodes are `DERIV004`. A dashed source stroke, or a source miter limit outside [1, 1000],
  read by evaluation is `DERIV_UNSUPPORTED`. Ancestor `clipContent` is ignored. The derived node
  gets `style.fillRule: nonzero`.
- **Knockout** = `target − offset(painted(cutters), clearance, join)`, round by default.
  `derive knockout` is sugar for that recipe; `--clearance-join miter|bevel` (with
  `--clearance-miter-limit`) only for fill cutters; with `--region` it first writes a hidden
  `intersect` derivation. Both forms fit the stage cap with the default tolerance feasible.
- Text-outline derivations and text operands are deferred; text outlining stays destructive
  (D-21).

### Evaluation

- In the **derived node's local space**: operands are mapped by
  `inverse(world(derived))·world(operand)` below their lowest common ancestor, with
  `DeterministicTrig`; strokes are built in each stroked node's own space, then mapped; distances
  and tolerance are derived-local units; moving, rotating or scaling a common group changes
  nothing. A singular map is `DERIV001`.
- Evaluation follows the D-21 stage model (at most four stages, one final boolean), its measured
  tolerance with fail-fast feasibility, its magnitude bounds and per-command budgets with
  cancellation; a failure writes nothing.

### Hashes (pure, cross-platform, no files or fonts)

- `inputsHash` uses the versioned two-level encoding `agd-operands/1` (sorted keys, fixed-precision
  numbers). Per referenced node, once per validation: a shape digest (type, geometry fields, fill
  rule, fill presence, own transform fields), a stroke digest (presence, width, cap, join, miter
  limit, dash array and offset) and a transform digest. The hash covers a header (op, canonical
  params with resolved defaults, tolerance, algorithm, the derived node's transform-digest chain
  below the common ancestor) and per operand its descriptor, shape digest, stroke digest whenever
  evaluation reads the source stroke, and its transform chain.
- Excluded: name, visibility, lock, order, opacity, colours, extension data, the common ancestor
  and above. `outputHash` is the SHA-256 of `d`.
- Aggregate work `Σ derivations (|derived chain| + Σ operands (1 + |operand chain|)) ≤ 2^18`, so
  hash work per validation stays within document bytes + 16 MiB.

### Validator, writes and checks

- Pure validator errors: `DERIV001` every static descriptor or params rule (unknown op, bad params
  including a miter limit outside [1, 1000], an offset of 0 or out of range, an operand offset
  outside boolean, a join without an offset, a miter limit without miter, miter or bevel on stroke
  or painted geometry, a singular transform), so `validate` reports it and patches cannot
  introduce it; `DERIV002` missing operand; `DERIV003` cycle or self-reference; `DERIV004`
  non-outlinable operand; `DERIV008` an arriving document over a limit (still detachable; rebuild
  refuses with `RESOURCE_LIMIT`). Warnings `DERIV005` stale and `DERIV007` edited fail strict
  pipelines by design. Algorithm-version notices are `info` in `derive check` only; no info level
  is added to the validator.
- `derive add` and `derive knockout` refuse the static miter or bevel case up front with
  `DERIV_UNSUPPORTED` and the two-step hint.
- A `d` write to a derived node is `DERIV_BAKED_GEOMETRY` unless the same patch detaches it;
  deleting or retyping a referenced operand is `DERIV_INPUT_REFERENCED` unless
  `--detach-dependents`; documents already failing `DERIV002` stay repairable.
- Rebuild is explicit (`derive rebuild`, or `rebuildDerived` on a patch for the derivations
  downstream of the patched nodes), in topological order (ties by document order), pinned to the
  revision read. A hostile stored document gets a typed error and stays byte-identical.
- `derive check [--recompute]` (read-only) reports `fresh|stale|stale-upstream|edited|invalid`;
  `--recompute` compares bytes, and adds `equivalent|differs` when bytes differ.
- Lint `LINT006` exempts derivation operands. `derive` commands use the store-free file engine and
  never create `./.agd`.
- Limits: ≤ 1024 derivations per document, ≤ 64 operands, depth ≤ 32, ≤ 2^18 work units.

| CLI | MCP |
|-----|-----|
| `derive add <doc> --op stroke\|offset\|boolean --operand id[:geometry[:offset[:join[:limit]]]]… [--param k=v…] [--parent id] [--name N] [--expected-revn]` | `derive_add` |
| `derive knockout <doc> --target id --cutter id[:fill\|painted]… --clearance C [--clearance-join …] [--clearance-miter-limit M] [--region id]` | `derive_knockout` |
| `derive rebuild [--node id…]`, `derive check [--recompute]`, `derive detach --node id…` | `derive_rebuild`, `derive_check`, `derive_detach` |
| `patch … [--rebuild-derived] [--detach-derived] [--detach-dependents]`; `delete … [--detach-dependents]` | patch and delete tools with the same flags |

Exit codes: `derive check` 0 fresh, 2 invalid, 6 stale, stale-upstream, edited or differs, 4 bad
arguments, 1 I/O; the other `derive` commands 0, 4 or 1 (D-27).

### Verification (slice S07)

- Equivalence: the D-21 dense and stroke-equivalence oracles on stroke derivations under ancestors
  scaled 2×, 2×1 and rotated 30°; deterministic rebuild bytes.
- A table-driven staleness matrix from the `agd-operands/1` field list (included field → stale,
  excluded → fresh; operand join and limit → stale; omitted join equals explicit round; source
  width also when overridden; gaining or losing a stroke; dash offset; a common group moved →
  fresh, an operand inside it → stale; `d` edit → edited; upstream → stale-upstream).
- Every limit at and one over; text → `DERIV004`; each `DERIV001` case through `validate` and as a
  refused patch; infeasible stored tolerance → `PATH_TOLERANCE_UNMET` without a write; the D-21
  hostile magnitude fixtures under `derive rebuild` and `derive check --recompute` leave the file
  byte-identical; no `./.agd`; the hash-amplification fixture within its bound; over-budget and
  cancelled rebuilds write nothing; deletion refusal, cascading detach, cycle and missing cases.
- Old-reader evidence: a hermetic proxy plus one recorded run of the published 0.3.0 bundle on
  committed fixtures (field preserved, baked `d` verbatim in SVG, PNG equal to a same-run render
  without the field).
- A two-strand interlace with opposite over and under at two crossings, at 16 and 512 px.

## Alternatives

- **Destructive commands only**: the recipe leaves AGD; the primitives ship anyway (D-21).
- **Live format-2 nodes or modifiers**: every consumer needs an evaluated-scene stage and old
  readers drop the content silently (0.3.0 exporters skip unknown nodes); remains the upgrade path
  and would reuse the same stroker and evaluator.
- **SVG `<mask>` knockouts**: SVG-only, invisible to geometry operations, and need format 2.
- **A separate knockout op**: equivalent to a boolean with operand descriptors.
- **Document-space evaluation**: contradicts live strokes under scaled transforms and makes every
  derivation stale when a whole mark moves.
- **A single-level hash over full operand encodings**: cost grows to tens of gigabytes for a
  hostile 16 MiB document.
- **Text operands with font identity in the hash**: staleness would become platform- and
  font-dependent.

## Revisit when

Agents routinely leave derivations stale despite the warnings; cross-document or text derivations
become necessary; a GUI needs live booleans.
