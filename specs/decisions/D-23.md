# D-23 Asset families: optical masters, variant axes and baked placements

**Decided by**: architecture review (capability design closure, all four lenses, change 007); the
owner chose baked placements with drift detection as the first persisted reuse (R-13); new file
format and document-format review when built · **Date**: capability design, pre-public history ·
**Cited by**: R-13, C-09, D-03, D-24, D-25, change 013 slice S08

Status: accepted; built by slice S08 of change 013, not opened yet. The family file is a new
format 1; `group.placement` is additive to the document format 1.

## Decision

### Family manifest

- `<name>.agd-family.json` (format 1, `schemas/agd-family.schema.json`) describes one logical
  asset. Names match `[a-z][a-z0-9-]{0,63}` and are unique.
- **Masters**: each is a document, or a **frame** sub-node (crop `frame-box`; any other node is
  `FAMILY006`), with an integer pixel size range. Ranges cover 1..∞ contiguously without overlap,
  the last open-ended; all masters share one aspect ratio (±1e-6).
- **Axes**: inline, or shared through `axesFrom` (an `.agd-axes.json` file serving a whole icon
  set). Each axis value applies, in declared axis order, `tokens` overrides, `recolor` (one colour
  or `{token}` for every fill, stroke and gradient stop, alpha kept) and `background`. DTCG
  `tokensFrom` is deferred; DTCG files are imported into members with `tokens import`.
- Limits: ≤ 256 KiB and depth ≤ 16 per file; ≤ 16 masters, 8 axes, 16 values per axis and 256
  overrides per value; unknown or duplicate properties are rejected.

```json
{ "version": 1, "name": "brand-mark", "axesFrom": "brand.agd-axes.json",
  "masters": [ { "id": "s16", "source": "mark/mark-16.agd.json", "sizes": { "min": 1, "max": 19 } },
               { "id": "display", "source": "mark/marks.agd.json", "node": "<frame id>", "sizes": { "min": 20 } } ] }
```

### Resolution and checks

- One Core `FamilyResolver` builds transient documents through the shared
  `TransientDocumentBuilder` (D-24): tokens kept, overrides applied, derivations stripped, crop
  and background declared. The pipeline, targets, sheets, analysis and kits all use it. Size
  selection uses the larger pixel dimension of the artwork box (output box minus padding); SVG
  outputs pass a nominal size.
- `family check` is a context check (not the pure validator) with `info|warning|error`; strict
  pipelines fail on error and warning, never info. Errors: member validation, `FAMILY001` coverage
  gap or overlap, `FAMILY002` aspect, `FAMILY003` unknown override token, `FAMILY005` recolour of
  an image, `FAMILY006` non-frame member. Warnings: `FAMILY004` literal paint not following an
  axis, member `DERIV005`/`DERIV007`, and in document mode `PLACE001` stale and `PLACE002` edited.
  Info: `FAMILY007` collapsed gradient.

### File-reference rule (shared with manifests and kits)

`axesFrom`, member `source` and `placement.family` (and every later reference) use the
`AssetPaths.Resolve` grammar (relative, `/`-separated, no `..`, not rooted), are confined to the
declaring file's directory (plus MCP confinement), are inspected before opening (no links, FIFOs
or devices) and read with a bound, and are never dereferenced by the pure validator. Shared files
therefore sit at or above their users; upward references and a project-root marker are deferred.

### Baked placement (`group.placement`)

- An additive `group.placement { family, variant, size, master, sourceHash, contentHash }` on a
  group that holds baked copied content. Live in-document instances stay deferred and
  owner-gated; a future instance node should reference the same `(family, variant, size)`.
- `family` resolves relative to the document file under the reference rule; store-backed
  documents are refused (`PLACE_STORE_UNSUPPORTED`).
- **Copy** from the variant's transient document: derivations stripped (nothing remapped); every
  `tokenRef` and `typographyTokenRef` paint baked to its value under the variant (placed content
  ignores the target's tokens); only `data:` images (`PLACE_IMAGE_UNSUPPORTED` otherwise); nested
  placements flattened to plain content (depth 1); `PLACE_CYCLE` when the target is a master of
  the family, transitively (≤ 8 levels, ≤ 64 files).
- **Geometry** (one rule, so bytes and `contentHash` agree): `size` is an integer 1–8192 in target
  units, the larger dimension of the artwork box, and selects the master by range. The group's
  single child is a **wrapper frame** (`clipContent`, the crop box as its size) whose transform is
  the contain fit of the crop box into the artwork box, centred, rotation 0; the group's own
  transform stays user-owned. A document master's root frame is copied intact as the wrapper's
  child (wrapper style null); a frame member's wrapper carries the frame's style (paints baked) and
  children. The canvas background is not copied; a variant background becomes a covering first
  rectangle. Trade-off: one placement shows one master; lockups needing per-size masters are
  themselves families.
- **Style boundary**: placed content never inherits target paint. Each copied null-style
  primitive with no styled container inside the copy gets the renderer default it draws in the
  master (`fill #000000`, or a black 1-unit butt, miter, 4 stroke for lines and open polygons).
  Target transforms, opacity and blend still apply.
- **SVG presentation fix** (a declared exporter defect fix S08 depends on): the exporter tracks
  inherited fill and stroke presentation from SVG's initial values, and an explicit style
  replaces the whole presentation state as in Skia (a stroke-free style means no stroke with
  SVG's initial stroke parameters; an omitted stroke parameter takes the document default). Only
  output where inheritance overrode an explicit style changes.
- **Ids**: copied ids are SHA-256-namespaced from (target document, group, source node); the
  wrapper and background add `#wrapper` and `#background` to (target document, group, crop root).
- **Hashes** (`agd-placement/1`): `sourceHash` over the resolved, overridden, paint-baked source;
  `contentHash` over the wrapper (fit, box, style) and subtree as written.
- **Refresh** re-selects by size and variant, keeps the group's id, transform and order, re-fits
  the (possibly different) master into the same artwork box and re-copies in one revision-pinned
  patch; an edited placement is `PLACE_EDITED` unless `--discard-edits`.
- Work bound: one resolution per distinct `(family, variant, master)` per command; ≤ 4096
  placement groups per document; cancellable. Renderers treat placements as groups; 0.3.0
  preserves the field.

| CLI | MCP |
|-----|-----|
| `family init <name> --master id=path:min[-max]… [--axes-from f]` | `create_family` |
| `family check <family\|doc>`, `family inspect <family> [--sizes …]` | `check_family`, `inspect_family` |
| `export <family> --size 32 --variant appearance=dark,paint=mono -o out.png` | `export_document` with `family`, `variant`, `size` |
| `family place <family> --into <doc> --parent id --size N --variant … --at x,y [--refresh [--discard-edits]]` | `place_family_member` |

Exit codes: `family check` 0 clean, 2 error, 3 warning, 6 stale or edited, 4 bad arguments;
`family place` 1 for `PLACE_*` (D-27).

### Verification (slice S08)

Depends on change 010's token fix, the SVG presentation fix, S05 (sheet and analysis selectors),
S06 (manifest references) and S07 (derivation-aware checks). Increments: grammar, resolver,
`family init|check|inspect` and family export; sheet, analysis and manifest selectors; placement,
refresh and `PLACE*`.

- Size selection at range boundaries with and without padding; each `FAMILY*` code; recolour
  fidelity; frame-member tokens; limits and unknown fields; reference confinement (absolute, `..`,
  link, FIFO) on both surfaces.
- Placement: id determinism; `PLACE001` from an axes edit, `PLACE002` from a hand edit,
  `PLACE_EDITED` and `--discard-edits`; paint baking under a conflicting `ink`; the cycle, image
  and store refusals; the placed render equals the master's fitted family export; a refresh that
  switches to a master with another canvas keeps the rendered box; a translated, clipped,
  non-canvas-sized root at opacity 0.5 places as it exports. Comparator: exact RGBA on
  pixel-aligned boxes, else `Σ|Δα|/(255·box px) ≤ 0.002` on boundary pixels only.
- Style boundary: a target ancestor with red fill, a 3-unit blue dashed stroke and a token fill
  over null-style masters; a styled frame over null-style children; a styled stroke-free frame over
  a null-style line and open polygon under a wide dashed ancestor; PNG by the comparator, SVG by a
  test-only presentation cascade. Documents without such inheritance stay byte-identical.
- 4096 groups at and one over; resolution counting; cancellation; 0.3.0 old-reader evidence.

## Alternatives

- **One document with a frame per master and metadata**: edits risk touching the other masters
  (still expressible through frame members).
- **In-document component sets with instances (format 2)**: every renderer must expand instances;
  the deferred live part of persisted reuse.
- **Lockups by hand copy** (owner option C): no cost, but drift goes undetected. **Live format-2
  instances** (owner option B): a large review and cost.
- **Keeping token references in placements, or merging variant tokens into the target**: renders
  the target's colours, or conflicts on shared names such as `ink`.
- **Remapping copied derivations**: stale on arrival under hashes covering the transform chain.
- **The fit scale in the group transform, or copying at native master units**: a master switch
  would mis-size the placement silently, or a range edit would change the lockup layout.
- **A default style on the wrapper**: Skia would drop a null-style line's default stroke and fill
  an open polygon. **Narrowing to targets without styled ancestors**: lockups style content
  through containers as the normal case.
- **Upward references or a project-root marker**: references in untrusted documents could reach
  outside their directory.

## Revisit when

Lockups need live updates; appearances need different geometry (an additive `when` condition on
masters); DTCG standardises modes; icon-set scale needs several assets per family file.
