# D-28 Platform registry and per-capability qualification

**Decided by**: architecture review (change 008 design closure: architecture, security,
operations and test approved); the owner chose the Apple silicon scope and the symlink rule (C-11)
· **Date**: macOS qualification design, pre-public history · **Cited by**: Q-05, C-11, P1.I-08,
P1.I-09, P1.I-02, P4.B-02, D-29, change 008

Status: accepted; built by change 008. Its first increment (the registry and
`get_capabilities.platform`) was implemented and reviewed in the pre-public history and is not yet
in this repository. The evidence sections below say how values become `qualified`: the output
corpus, the qualification record, the claim check, merge evidence and the runner.

## Decision

### Owner choices and premises

- Qualify **Apple silicon osx-arm64, APFS, macOS 26 or later only**; Intel Macs, older macOS,
  non-APFS volumes, Linux arm64 and Windows pixel backends stay refused.
- A **strict symlink rule** with exactly three verified system aliases (`/var`, `/tmp`, `/etc`);
  every other link stays refused; resolving every root with `realpath` is rejected.
- The platform class of raster outputs is decided once a Linux-to-macOS output corpus comparison
  exists (recommended outcome below).
- An established premise, not an owner choice: one release bundle stays, RID-less, framework-dependent tool packages, each platform qualified
  over identical package hashes; no per-platform build.

### Core platform registry (`Core/Platform`; change 008 owns it, change 009 consumes it unchanged)

- `PlatformCapability`: `vector`, `rasterExport`, `assetPipeline`, `artifactVerify`,
  `stillImport`, `nativePixels` (stable camelCase wire names). `CapabilityQualification`:
  `qualified` (admitted and the pair cites a committed record), `unqualified` (admitted, no
  evidence, no support claim), `refused` (fails closed with `ASSET_PLATFORM_UNSUPPORTED` before any
  write).
- `PlatformProfile.Current` (computed once, I/O-free) and `For(os, process architecture, runtime
  version, OS version)`; the profile is `dotnet{major}-{os}-{arch}` using the **process**
  architecture (a Rosetta process is x64). `GateAdmits(c)` is `qualification != refused`;
  `RefusalMessage(c)` lists the qualified profiles and minimum OS versions and contains no path;
  `Refusal(c)`; `QualifiedProfiles`; `ToCapabilitiesJson()`. The OS floor is decided by `For` from
  its argument, never by a separate OS check. Gates read only `Current`; a test seam can only lower
  a policy.
- Stable vocabulary: the `requires` key `filesystem` with value `apfs`; probe reasons
  `GATE_REFUSED`, `FILESYSTEM_UNQUALIFIED`, `FILE_LOCKING_DISABLED`, `ROOT_UNAVAILABLE` or null;
  fact keys `filesystem`, `caseSensitive`, `fileLocking`, `rootCanonical`. Adding a value is
  additive; renaming is a cutover. The registry references no file API, P/Invoke or evidence file
  (an architecture test enforces it).
- Invariants: an admitted `stillImport` implies an admitted `nativePixels`; refused policies have
  empty `requires`; every qualified pair has exactly one evidence entry.
- A read-only live availability probe (`PlatformAvailability.Default.Probe(capability, root)`)
  uses only the drive format, `pathconf(_PC_CASE_SENSITIVE)` on Darwin, the file-locking helper and
  the canonical-path entry point; `available` is false with `GATE_REFUSED` when refused, else false
  with the first failing check's reason, true when every check passes, null only for `vector` and
  `rasterExport`.

**End state** (after the final qualification):

| Profile | vector, rasterExport | assetPipeline, artifactVerify | stillImport, nativePixels |
|---------|----------------------|-------------------------------|---------------------------|
| dotnet10-linux-x64 | qualified | qualified | qualified |
| dotnet10-osx-arm64, macOS ≥ 26.0 | qualified | qualified | qualified `{filesystem: apfs}` |
| dotnet10-osx-arm64, macOS < 26.0 | unqualified | refused | refused |
| dotnet10-windows-x64 | unqualified | unqualified | refused |
| anything else (osx-x64, linux-arm64, windows-arm64, runtime ≠ 10) | unqualified | refused | refused |

`rasterExport: qualified` means functional qualification; byte identity follows the corpus rule.

**Value staging**: values change only together with the enforcement and evidence behind them.
Stage S0 (the first increment) equals today's enforcement (osx-arm64 vector and raster
`unqualified`, the rest `refused`; only linux-x64 qualified); S1 admits asset inspection
(`unqualified`); S2 admits still import and native pixels (`unqualified {apfs}`) once the Darwin
backend, fixtures and stored-name gate merge; S3 marks the osx-arm64 row `qualified` with
`minOsVersion` 26.0 together with a committed qualification record. S0 narrows Windows: arm64
and runtime ≠ 10 become refused, declared in the changelog.

**Gate map**: `assetPipeline` at every pipeline inspection and lint inputs; `artifactVerify` at
artifact preflight; `stillImport` at the import input (the target then passes the `nativePixels`
gates); `nativePixels` at backend selection, store inspection, the lock-path inspection and the
backend preconditions. Refusals rethrow the registry text unchanged.

**`get_capabilities.platform`** replaces `supportedPlatform` and `currentPlatformMatches` (a
declared direct cutover, no alias): `architecture`, `capabilities[] {capability, qualification,
requires}`, `os`, `osVersion`, `profile`, `qualifiedProfiles[] {capabilities, minOsVersion,
profile, requires}`, `runtimeVersion`; object keys ordinal-sorted at every level, arrays in enum
and table order, byte-stable, no top-level `qualified` boolean. Golden fixtures per profile tuple
are built from synthetic versions and byte-compared; host assertions compare with `Current`.

### File backends

- **Asset inspection** reuses the runtime's platform-neutral `lstat` (FIFO, regular and link
  modes verified); a hand-mapped Darwin `lstat` or link-target checks are rejected.
- **Native pixel storage** delegates to a backend chosen purely from the profile (Linux x64 code
  moved verbatim, Darwin arm64, or unsupported); decisions are pure functions over a syscall seam
  testable on every OS.
  - Identity: Darwin `lstat`/`fstat` (dev, mode, nlink, ino) cross-checked against the runtime; a
    mismatch is `PATH_ESCAPE`; the lock file must match its path identity, be regular and
    single-link.
  - Publish uses only `renamex_np(RENAME_EXCL | RENAME_NOFOLLOW_ANY)`, replace
    `RENAME_NOFOLLOW_ANY`, on canonical paths; never link-and-unlink, check-then-rename or a copy.
    An up-front flag probe on a staging file turns `EINVAL`, `ENOTSUP` or `EOPNOTSUPP` into
    `ASSET_PLATFORM_UNSUPPORTED`, removing its staging.
  - Preconditions before staging, each refused with its own stable path-free message: APFS
    ("native pixel storage requires an APFS volume"), file locking enabled ("file locking is
    disabled for this process"; this also tightens Linux), and the flag probe ("the volume does not
    support no-replace, no-follow rename"). Locking detection follows the runtime's own switch and
    environment-variable rule exactly.
  - Errno mapping: `EEXIST` and `ENOTEMPTY` → `PIXEL_ALREADY_EXISTS` on publish; `ELOOP` →
    `PATH_ESCAPE`; `EXDEV` → `STORE_UNAVAILABLE` (never a copy fallback); `ENOTSUP`, `ENOSYS`,
    `EOPNOTSUPP` → `ASSET_PLATFORM_UNSUPPORTED`; contention (Darwin 35, Linux 11) retries within
    5 s, then `PIXEL_BUSY`; any other errno publishes nothing (`STORE_UNAVAILABLE`).
- **Canonical paths**: `PlatformPaths.FullPath(path, base?)` is the only way user or config input
  becomes a trust-relevant path: full path, then on macOS a leading `/var`, `/tmp` or `/etc`
  becomes `/private/<name>` only when it is a uid-0 link whose target is exactly `private/<name>`
  and that directory is a root-owned real directory (verified once per process), then the
  existing strict walk, then the same string for every open, lock, rename and comparison. The MCP
  root, every argument and the reported `workingDirectory` are canonical. A repository check bans
  raw `Path.GetFullPath`, `FullName` of non-enumerated values and unchecked
  `Path.GetRelativePath` outside this entry point.
- **Stored-name rule** for pixel writers: a writer addressing an existing asset requires the
  stored leaf name (Darwin `getattrlist` name; Linux the requested leaf) to be byte-equal to the
  requested leaf, checked before and after taking the lock; a case or normalization alias is
  `PATH_ESCAPE`. Create is unchanged (`RENAME_EXCL` refuses an alias).
- **One redactor**: Core `PathRedactor` replaces the separate CLI, MCP and SVG-import sanitizers;
  an absolute Unix, drive or UNC path that starts a token is replaced with its last segment, keeping
  trailing punctuation; relative paths, URLs, media types, fractions and `#/` pointers stay;
  paths with spaces and non-token-start paths are documented residuals.

### Raster platform class

Outcome A (all identical) claims byte identity for the measured hosts; outcome **B (recommended
wording)**: SVG, JSON and native-pixel outputs identical, rasters differing, stated as "raster
exports are byte-reproducible per producer host; `assets check` on rasters reports stale on a host
with different raster bytes"; outcome C (an SVG, JSON or native difference) is a determinism defect
that blocks the macOS claim. `assets check` stays byte-exact, with no tolerance.

### Residuals (stated in the support documentation)

File locking of the vector store, the asset-output lock and the MCP document lock is unchanged;
external APFS volumes with ignored ownership; file-provider trees with dataless files; Linux ext4
casefold directories; the macOS compatibility-version mode fails closed.

### Output corpus

- Repository-check commands (C#, no shell tools): `corpus --out`, `corpus-compare <a> <b>` and
  `corpus-extract <log>`. The corpus drives the built `agd` in a fresh temporary root: the valid
  examples exported to SVG, PNG at 1× and 2×, JPEG and WebP; `assets build` over a committed
  manifest; native-pixel create, edit and export; a seeded document and a serialize round trip,
  including a rotation case. Every render uses committed OFL-1.1 test fonts (Noto Sans and Noto
  Sans Arabic), registered with hashes and notices (D-01).
- Classes: `bytes` (SVG, serialized JSON, pipeline SVG and sprite outputs, by SHA-256);
  `normalized` (native-pixel decoded samples and canonical metadata without the listed identity
  fields); `raster` (PNG, JPEG, WebP: byte hash, decoded RGBA hash, size, maximum channel delta,
  differing-pixel count).
- Rules: two runs per host, any within-host difference exits non-zero with no record; any failed or
  refused output writes no record; only the `full` profile decides; records from different sources,
  manifests or font sets refuse to compare. The record (≤ 64 KiB) is carried as one line between
  log markers with its SHA-256, never as a CI artifact. The Linux side runs as a dispatch-only CI
  job at the same commit as the macOS run.

### Qualification record

- `platform-qualify --bundle <dir> --bundle-origin local-build|release-candidate --anchor <a>`
  writes one machine-readable record; `verify-record` checks schema, digest, completeness, zero
  failures and skips only from `.config/os-specific-skips.txt`; `verify-merge --base --head` adds
  the descendant rule and refuses a head that is not the pull request head.
- Completeness (one profile, no reduced CI form): Core, Skia, CLI and MCP suites in three root modes
  (the per-user temporary directory under `/private/var/folders`, a 0700 directory under
  `/private/tmp`, a directory under the account's home), each with tests discovered and its real
  path checked; the installed CLI and MCP suites in two modes after the restore and verify scripts
  under `/bin/bash` 3.2; every script exit 0; a `full` corpus digest; a quarantine install check.
- The record binds the source commit, bundle origin and anchor, package hashes, OS build and
  version, RID, SDK and runtime, CPU, filesystem and case sensitivity, per-mode paths and counts
  with skip reasons. A `local-build` record is not release evidence; only a `release-candidate`
  record, whose anchor is the `SHA256SUMS` digest printed by the same run that built the bytes,
  supports a release claim. The record is an unsigned self-report, so release records are run by
  the lead outside any CI runner account.
- Release-time macOS record: the lead builds the release candidate on the qualified Linux host and
  commits its log; the owner attaches those bytes to a draft release; the lead downloads them on
  Apple silicon, runs `platform-qualify --bundle-origin release-candidate`, and commits the record
  before the release is published. Without the record a release does not name osx-arm64.
- Project documentation names osx-arm64 as qualified only for a release that has a
  `release-candidate` record; before that it says development source additionally qualifies
  osx-arm64 (macOS 26 or later, APFS).

### Claim check and merge evidence

- `.config/qualification-evidence.json` lists one entry per qualified (profile, capability) pair:
  `kind: d10` (the record names its own source commit S) or, for linux-x64 only, `pre-d10` (a
  source commit and anchored line patterns over an existing qualification record). The pre-public
  design pointed the `pre-d10` entries at records that are not in this repository; the port
  re-points them at evidence available here.
- The **claim check** (repository gates, full history, every CI event) evaluates the checked-out
  head as it is (a synthetic merge ref included): the record passes `verify-record`, names the
  pair, S is an ancestor of the head, and the evidence file at S already listed the pair. It never
  applies the descendant rule. Archiving a record path updates the entry in the same diff.
- **Reachability of S (open, inbox)**: the pre-public design merged a pull request that adds or
  changes a `d10` entry with a merge commit, never squash, so S stayed reachable. This
  repository's main ruleset allows only squash merges and requires linear history, and merge
  commits are disabled, so a squash merge leaves a pull-request-head S unreachable from main and
  the claim check could never pass after merge. The rule is redesigned at 008/T015 and 008/T018
  for one of two choices: the recommended two-step flow, in which the code merges first,
  qualification runs on the resulting squash commit on main, and a results-only pull request then
  adds the record and the `d10` entry (its squash keeps S an ancestor, and merge evidence accepts it
  as results-only); or an owner-granted ruleset exception that allows merge commits for `d10`-entry
  pull requests. Until one is chosen, no `d10` entry is added and this decision claims no merge
  method.
- **Merge evidence** (`verify-merge`, run by the lead): a record with source S is evidence for head
  H when S = H, or S is an ancestor and only results and acceptance files changed. Evidence before
  merge, by phase:

  | Phase | Pull requests bound | Evidence before merge |
  |-------|---------------------|-----------------------|
  | P0 (until 008/T018 merges) | PR-1 (008/T001, 008/T002) | Linux CI, plus a local macOS run of the 008/T002 test classes on the pull request head in `private-tmp` mode; those classes must pass |
  | P0 | change 008 pull requests that change `src/`, `tests/` or a supported script, each after 008/T003 | Linux CI, plus an interim `macos-progress` record for the head whose failure set only shrinks (new skips or OS-guarded early returns fail unless listed with a reason) |
  | P0 | PR-0, documentation-only pull requests, the runner script and workflow (008/T016a, 008/T016b) and every sibling change's pull requests | Linux CI only |
  | P1 (from 008/T018) | every pull request touching `.config/platform-sensitive-paths.txt` paths, sibling changes included | Linux CI, plus a complete zero-failure record that is evidence for the head: a green macOS CI log record or a committed lead-run record |

  A skipped, cancelled or timed-out macOS run is never evidence.
- Tests never pass vacuously: OS-guarded early returns become platform fixtures or skips with a
  reason, and a repository check bans them.
- Scripts stay `/bin/bash` 3.2 and BSD compatible (`tr` lowercasing, a portable same-parent `mv`, a
  `sha256sum`/`shasum` helper), enforced by a bash 3.2 lint.

### macOS CI runner

Which runner the public repository uses is open with the owner (inbox). The pre-public choice was
a repository-scoped self-hosted runner on an owner-operated Apple silicon machine under a separate,
hidden, non-admin `_agd_ci` account; that design applies only if the owner chooses it again, and on
a public repository fork workflows must then require approval:

- `scripts/setup-macos-runner.sh` modes `--dry-run`, `--install`, `--audit [--extra-path]`,
  `--audit-self-test`, `--enable`, `--check`, `--teardown`; `/bin/bash` 3.2, idempotent. The audit
  fails if the account can read the owner's home, repositories, SSH, keychain, `gh` or Docker
  credentials, another CI account's home or the Docker socket, run `sudo -n`, or hold any
  credential; `--enable` loads the daemon only after a passing audit; a missing account is a
  distinct exit code that never counts as a failing run.
- Root boundary: once the account exists, root never executes, sources, copies from, changes owner
  of or follows a path the account can write; the audit runs from a root-owned copy; the
  LaunchDaemon definition is regenerated, never copied. The registration token never appears in
  argv, a file or a log; the runner and SDK downloads are verified against committed hashes, and the
  SDK version follows `global.json`.
- The `test-macos` job lives in its own workflow, gated by a repository variable and same-repository
  pull requests, with `contents: read`, no secrets, no persisted credentials, a head-SHA checkout,
  a timeout, per-ref concurrency, documentation-only path filters and per-job package isolation,
  all enforced by a workflow lint. It produces a complete record.
- Accepted risk: a persistent runner can be tampered with by a writer's job, so its records are only
  as trustworthy as the writers; release records are run outside the account.

With a GitHub-hosted Apple silicon runner instead, the job keeps the same permissions, checkout and
completeness rules, and the account and provisioning rules do not apply.

## Alternatives

- A compatibility alias for the old fields (against direct cutover); a two-valued status (cannot
  describe Windows); probing inside `get_capabilities` (not I/O-free); end-state values from the
  first increment (reporting would drift from enforcement); skipping aliases in the walk; a
  per-parent pixel lock or .NET case folding (not APFS folding); enumerating to find the stored name.

## Revisit when

A recorded run exists for another macOS major or profile; the owner qualifies another platform
(C-11); the corpus shows a determinism defect.
