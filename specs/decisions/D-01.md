# D-01 Dependency policy and exact approvals

**Decided by**: owner · **Date**: project start, with a later permissive-license clarification · **Cited by**: C-01, C-02

## Decision

No package enters the resolved graph unless all of these hold:

1. Its license is MIT-compatible permissive (MIT, Apache-2.0, BSD, Boost and similar). GPL,
   LGPL, AGPL and MPL are prohibited. AGD's own code stays MIT; each component keeps its own
   license and required notices. No copyleft exception is granted for runtime host utilities.
2. The exact package id and resolved version have a machine-readable approval, covering every
   scope it resolves in (runtime and/or test). Family or prefix wildcards are not approvals.
3. Direct versions are pinned centrally and lockfiles restore in locked mode.
4. The structured NuGet vulnerability audit, run through an isolated, forced, locked restore
   with failure-visible coverage counters, reports no known vulnerability and no incomplete
   retrieval.
5. Required managed, native and bundled-data notices exist in `THIRD-PARTY-NOTICES.txt`,
   including one for each third-party component compiled into a redistributed native binary,
   and each required notice records the licenses it reproduces, which rule 1 must allow.
   A package's own third-party notice file may instead be redistributed byte for byte beside
   it as a declared upstream notice, pinned by SHA-256 to the copy in every package that ships
   it (`THIRD-PARTY-NOTICES-SKIASHARP.txt` for the SkiaSharp and HarfBuzzSharp native assets);
   required notices may point into it, and `THIRD-PARTY-NOTICES.txt` supplements it for the
   compiled components it omits. Both files ship at the root of each tool package.
   Bundled non-package data (the Inter font, SIL OFL 1.1) is recorded with hashes, license and
   notice marker.
6. Runtime features stay available to self-hosted users without SaaS-only dependencies (C-02).

The approval registry `.config/dependencies.json` is authoritative for ids, versions,
licenses, scopes, notice markers and upstream notice hashes. `scripts/check-dependencies.sh`
and `scripts/check-vulnerabilities.sh` (backed by `scripts/RepoChecks`) enforce it in CI; the
exact audit profile lives in that checker and its self-tests. Before adding or upgrading a
package: verify upstream license metadata and file, run the audit, update the pin, lockfiles,
approvals and notices, and record the change in the pull request.

A permissive license does not establish correctness or security. Package metadata is not a
trust oracle; license classification and notice content still need review on every change.

## Alternatives

- Allow any OSI license — rejected: copyleft would constrain self-hosters and embedders.
- MIT-only dependencies — rejected by the owner: excludes sound permissive components such as
  the Apache-2.0 MCP SDK and Boost-licensed Clipper2.
- Range or family approvals with text-parsed audits — replaced during 0.1: they let new
  transitives in silently and hid incomplete audits.
- Rejected packages: SixLabors.ImageSharp (split commercial terms); copying Penpot (MPL) code.

## Revisit when

The owner changes licensing policy, a needed capability has no permissive option, or the
pinned SDK or NuGet audit behavior changes.
