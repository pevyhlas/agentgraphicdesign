# D-24 Asset manifest v2 and platform target adapters

**Decided by**: architecture review (capability design closure, all four lenses, change 007);
export and pipeline review when built · **Date**: capability design, pre-public history ·
**Cited by**: R-05, D-07, D-10, D-23, D-25, change 013 slice S06

Status: accepted; built by slice S06 of change 013, not opened yet. Typed, pure target adapters
are intended scope (N-05); atlas packing stays with change 014.

## Decision

### Manifest version 2

- `version: 1` files keep the exact v1 grammar and meaning. `version: 2` accepts only the new
  spellings; a v2 construct under `version: 1` is an error, and a v1 spelling under `version: 2`
  too.
- v2 adds: `outputRoots` (several disjoint roots, each exclusively owned, inventory per root);
  format-scoped `defaults.svg` and `defaults.raster`; `family` plus `variant` in place of `source`
  (after S08, D-23); `size` (an integer or `{width, height}` box, contain fit
  `s = min((W−2px)/cw, (H−2py)/ch)` centred on whole pixels); `viewport` (the v1 crop, exclusive
  with `size`); `padding` (`{ratio}` 0–0.45 per side, or `{pixels}`); `background`; `opaque`
  (render into an opaque surface so the PNG has no alpha channel, through an additive
  `RenderOptions.Opaque`; needs an opaque background, else `ASSET_NOT_OPAQUE`); `scale` in
  (0, 1000], bounded by 8192 px per side and the pixel budget instead of 0.1–4; an optional `kit`
  block (D-25).

```json
{ "version": 2, "outputRoots": ["generated/web", "generated/apple"],
  "defaults": { "strict": true, "svg": { "currentColor": null }, "raster": { "fontDirs": ["fonts"] } },
  "assets": [ { "family": "brand/mark.agd-family.json", "variant": { "appearance": "dark" },
      "output": "generated/web/mark-dark-64.png", "options": { "size": 64, "padding": { "ratio": 0.08 } } } ],
  "targets": [ { "type": "ico", "family": "brand/mark.agd-family.json", "sizes": [16, 32, 48, 256],
                 "output": "generated/web/app.ico" } ] }
```

### Shared `TransientDocumentBuilder`

One Core builder replaces ad hoc in-memory copies for fit, padding, background, family
resolution, sub-node export (D-10) and analysis regions. Inputs: source (document or
`document#node`); tokens (copied, then overrides; never dropped); background (`source`, `none`, a
colour); crop (`canvas`, `ink`, `frame-box`); fit (contain, padding, integer-pixel centring); a
visibility mask (analysis regions, ancestors kept); derivations always stripped. Change 012 lands
its first part (D-26); S06 adds `frame-box`, fit and padding. The sub-node token defect is fixed
first by change 010.

### Target adapters

- `targets[]` is a closed set selected by `type`, with no registry (D-07). Adapters live in
  `Core/Assets/Targets/` above rendering; `IExportAdapter` is unchanged.
- Requests are a closed union: `RasterRender(ref, variant, pixel box, padding, background,
  opaque)`, `SvgExport(ref, variant, nominal size, currentColor)` and `ResolvedTokens(family,
  appearances, token names)`. `Plan(spec)` and `Package(output, results)` are pure; results are
  raster images, SVG documents and token values.
- The host keeps planning validation (confinement, collisions, case aliases, derived names,
  budgets), execution through the vector producer or the family resolver, comparison, inventory
  and per-file publication. Adapters never touch the filesystem or the renderer.

| `type` | Outputs |
|--------|---------|
| `ico` | ICONDIR with PNG entries 1–256 (256 written as 0), ascending, unique |
| `icns` | PNG elements 16–1024 including the @2x OSTypes; optional `iconset` |
| `apple-appiconset` | `Contents.json` and a 1024 universal entry with `dark` and `tinted` luminosity appearances; `any` is opaque |
| `apple-colorset` | `<token>.colorset/Contents.json` (sRGB, any and dark) plus a root `Contents.json`, from resolved tokens only |
| `web-icons` | PNG per size, maskable PNGs (padding ≥ 10 %, opaque) and an icons-fragment JSON; the app's web manifest stays consumer-owned |
| `hicolor` | `<N>x<N>/apps/<name>.png` and `scalable/apps/<name>.svg` |
| `favicon` | a preset expanding to `ico` 16/32/48, `favicon.svg` (nominal 32) and `apple-touch-icon.png` (180, opaque); no container code of its own |

Every raster size is rendered from vectors, never downsampled from a large render; no dependency
is added. Derived path components (token names, the hicolor `name`) match
`[A-Za-z0-9][A-Za-z0-9._-]{0,63}` and are unique case-insensitively, else `ASSET_TARGET_INVALID`.
JSON is written with fixed key order, LF and a trailing newline. Apple key sets and OSTypes are
frozen in S06 against committed reference fixtures.

### Safety, limits and surfaces

- No input (manifest, sources, family and axes files, members, files read through placements,
  font directories) may lie under any output root or the kit root; index and iconset paths stay
  inside a root; violations are `ASSET_PATH_UNSAFE`.
- `assets build|check` refuse a manifest with a `kit` block (`ASSET_KIT_MANIFEST`), so kit
  outputs are written only by the kit publisher (D-25); `assets plan` is allowed.
- Limits: ≤ 64 targets, ≤ 32 sizes per target, ≤ 4 appearances, ≤ 16 roots; each request is one
  occurrence against the existing 256; ≤ 4096 planned outputs; the existing 64 MiB total, 32 MiB
  per asset and 64 Mpx budgets.
- Diagnostics: `ASSET_SAFE_ZONE` (warning, shared with analysis: the artwork-alone render has
  pixels with α ≥ 128 outside the 0.4·W circle), errors `ASSET_TARGET_INVALID`,
  `ASSET_NOT_OPAQUE`, `ASSET_VARIANT_UNKNOWN`, `ASSET_KIT_MANIFEST`.
- Parity: CLI `assets plan|build|check` (plan is render-free); MCP `plan_assets`, `check_assets`
  and `build_assets`, confined; the pipeline leaves CLI-only. Exit codes: 0, 2 strict findings,
  6 drift, 4 bad arguments, 1 typed error (D-27).
- On macOS the pipeline works only once change 008 admits file inspection there.

### Verification (slice S06)

Depends on change 010, S05a (raw RGBA and coverage, D-26) and change 008 (macOS inspection and the
reference fixtures). Increments: v2 grammar with fit, padding, the builder, `Opaque` and the MCP
tools; `ico` and `favicon`; the Apple adapters once fixtures exist; `web-icons` and `hicolor`.

- Test oracles independent of the writers: ICO through Skia's codec, a test-only reader and
  hand-built golden bytes; ICNS through a test-only reader, PNG chunk CRCs and a committed
  `iconutil` reference; appiconset and colorset goldens plus a committed `actool` reference;
  opaque PNGs have IHDR colour type 2; a maskable out-of-circle fixture.
- Writer evidence, recorded on Apple silicon macOS 26 or later and repeated at the integrated run:
  `iconutil --convert iconset` on AGD's `.icns`; `actool --compile … --errors --warnings` on AGD's
  xcassets once per targeted platform (iphoneos for the universal appiconset; iphoneos and macosx
  for colorsets); `sips` decodes every element. Linux CI reports these as unverified until the
  macOS run is recorded.
- The v1 suite byte-for-byte against the post-S04 baseline (the changelog notes possible drift on
  curve-bearing rasters); mixed SVG and PNG under v2; 16 px from a 1024-unit canvas and 1024 px
  from 16; pixel-exact fit and padding goldens; overlap rejection for every input kind; name rules;
  several roots; a budget measurement for a full platform set; every limit at and one over;
  read-only proofs. PNG bytes are reproducible per platform only.

## Alternatives

- **Additive v1 fields and per-container kinds**: one entry per file and host code per container.
- **Separate `agd icons` commands**: no drift check, ownership or kit integration.
- **Containers as export adapters**: the wrong shape for outputs needing several renders and
  files.
- **BMP ICO entries**: PNG entries cover every supported Windows release.

Assumptions: Apple and Microsoft layouts are frozen against committed fixtures; PNG bytes are
reproducible per platform; the budgets suffice for a full platform set (S06 measures it).

## Revisit when

A container needs a library (D-01); the budgets block real kits; sprite or tile producers make
atlas adapters applicable (change 014).
